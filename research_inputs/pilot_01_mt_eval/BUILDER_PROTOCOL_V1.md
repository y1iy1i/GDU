# Pilot 01 盲 Builder 最小运行协议 v1

> 状态：已冻结  
> 版本：`pilot-01-builder-protocol-v1`  
> 日期：2026-08-18  
> 冻结时间：`2026-08-18T16:31:00+0800`  
> 目的：在不泄露 Gold 的条件下，对冻结论文执行一次 Schema 无关的盲构建。

## 1. 已确认：来源输入与权威性

### 允许输入

- `paper.pdf`：权威原文，SHA-256 `268ad0f67004844b252e80fee7f6f1724fc9a52506956f7e15b5cd2601371752`。
- `paper.txt`：搜索与定位辅助，SHA-256 `34f1b86c82eb5eef5547bf6a7c09317b28ad51e3ed7cf985406104456f68ca63`。

### 使用规则

- PDF 是唯一权威内容来源。
- `paper.txt` 只能用于关键词搜索、候选位置发现和快速导航，不能独立支撑正式判断。
- 由于论文为双栏排版，提取文本可能交错左右栏；正式阅读顺序、表格数值、图注、页码和证据必须回到 PDF 核验。
- 证据页码使用从 1 开始的 PDF 物理页码。
- PDF 与文本提取物发生冲突时，以 PDF 为准，并在构建记录中保留冲突。

### 禁止输入

- `GOLD_V1.md` 与 `GOLD_V1.sha256`；
- `GDU_DISCUSSION_LOG_V2.md`；
- 当前对话及其中出现的论文解读；
- Gold 评分规则、Gold 派生摘要或任何论文特定提示；
- 外部论文摘要、解读、作者访谈或相关资料。

## 2. 已确认：通用构建规则的详细程度

Builder 获得完整的通用 GDU 构建方法，但不获得任何针对本篇论文的答案、重点提醒或评价线索。目标是检验既定方法能否实例化到未知文档，而不是要求模型自行发明 GDU 方法。

### 四层通用流程

1. **物理与来源层**：确认来源身份、物理页、可观察标题和版面对象。
2. **局部语义层**：划分来源锚定的语义单元，生成原子判断并绑定证据。
3. **关系与全局计划层**：发现局部及跨章节关系，恢复目标、核心意义、内容选择、组织方式和约束。
4. **双向核验与冻结层**：用全局理解回查局部，用局部证据修正全局，保留重要替代解释和修订，再执行停止检查。

### 六个必经检查点

1. 来源与可观察物理结构；
2. 语义单元边界及局部功能；
3. 原子判断、认识论身份与直接／组合证据；
4. 单元—单元及判断—判断关系；
5. 五问式 GenerativePlan；
6. 全局—局部一致性、证据完整性、稳定性与停止状态。

### 通用认识论规则

- 区分作者明确／可蕴含内容与 Builder 的分析性解释。
- 先生成关系或计划候选，再回到 PDF 做定向核验。
- 不把“可能解释”升级为已证实因果，不把局部实验外推为普遍规律。
- 对有根据的竞争解释保留主要解释、替代解释及其证据差异。
- 后续全局理解可以修正早期主干，但关键修订必须进入构建记录。
- 只在覆盖、证据和稳定性联合条件满足时正式结束；否则输出暂定快照及未完成项。

### 防止论文特定答案泄漏

- 通用规则不得出现论文中的模型名、模板编号、语言对、具体实验结果或 Gold 判断。
- 不提供“重点检查某表格／某冲突／某结论”等针对本文的提示。
- 协议只描述所有文档都适用的理解动作和输出要求。

## 3. 确认状态

- 内容决策已完成；完整性与论文特定答案泄漏检查已通过，协议 v1 已冻结。

## 4. 已确认：首轮交卷形式

首轮输出为 Schema 无关的结构化 Markdown 文件 `BUILDER_OUTPUT.md`，不直接生成最终 `gdu.json`。

### 七个逻辑部分

1. 来源身份；
2. 可观察物理结构；
3. 语义单元；
4. 原子判断；
5. 关系；
6. 五问式 GenerativePlan；
7. 证据索引。

### 临时稳定编号

- `U-###`：语义单元；
- `A-###`：原子判断；
- `R-###`：关系；
- `E-###`：证据。

所有关系、计划判断、限制和解释都通过编号引用已经列出的对象，不靠模糊自然语言指代。编号只要求在本次冻结输出内稳定，不预先决定最终 Schema 的字段或嵌套方式。

### 最低表达要求

- 判断标明作者归因内容或 Builder 分析性解释，并标明内容、功能、计划或显著缺失类别。
- 关系只使用单元—单元或判断—判断两个端点层级。
- 证据使用 PDF 物理页码、所在章节／表图和简短定位信息；文本提取物不是独立证据。
- GenerativePlan 引用已经建立的判断和证据，不成为第二套事实来源。
- 有根据的竞争解释必须并列呈现，不强行合并为单一结论。

## 5. 已确认：轻量构建与修订记录

除 `BUILDER_OUTPUT.md` 外，Builder 单独生成 `BUILD_TRACE.md`，记录带顺序与时间标记的重要构建事件，不保存完整内部思维过程。

### 必须记录的事件

- 初始构建计划和计划发生的实质变化；
- 六个检查点的开始、完成或未完成状态；
- 触发定向重读的重要疑点或新证据；
- 会改变语义单元、主干判断、关系或 GenerativePlan 的修订；
- 高影响竞争解释的保留、淘汰或主次变化；
- 最终停止门检查及尚未完成的事项。

### 修订事件的最小字段

- 事件编号与 ISO 时间；
- 所属阶段；
- 触发原因；
- 修改前的对象引用与简短内容；
- 修改后的对象引用与简短内容；
- 支持修改的证据编号；
- 对其他对象的影响；
- 是否仍保留替代解释。

### 不记录的内容

- 逐 token 或逐句内部思维；
- 没有改变理解对象的措辞润色；
- 重复搜索、重复确认和无结果的常规操作；
- 无法由输出对象或来源证据核验的自我叙述。

轻量记录用于研究“后来的全局理解怎样改变早期局部主干”，而不是把冗长过程本身当作正确性的证据。

## 6. 已确认：检查轮次与停止门

### 三轮主流程

1. **局部自下而上构建**：完整阅读来源，建立物理结构、语义单元、初步判断和证据。
2. **全局自上而下构建**：发现跨章节关系，恢复 GenerativePlan，并用全局理解检查局部功能与判断。
3. **双向核验**：定向复核高影响结论、表图、限制、认识论身份、证据和全局—局部一致性。

### 联合停止门

- **覆盖度**：重要章节、核心论证链和限制已经进入结果，未覆盖处明确列出。
- **证据度**：持久判断与关系均已完成证据检查；无法确定者明确标为不确定，不用推测补齐。
- **稳定度**：最近一次核验不再改变主干判断或 GenerativePlan；仍有变化则说明尚未稳定。

只有三项同时满足，才输出正式完成状态。

### 有界定向修正

- 停止门未通过时，最多执行两次由具体缺口触发的定向重读与修正。
- 每次只重读与缺口相关的页面，并在 `BUILD_TRACE.md` 记录触发原因、对象变化和证据。
- 两次后仍未通过时，输出暂定快照、未完成项和失败的停止条件，不继续无界循环，也不为满足格式强行生成结论。

循环上限按逻辑修正轮次计算，不按底层模型调用次数计算；模型调用与失败重试另行规定。

## 7. 已确认：上下文与文件系统隔离

盲 Builder 必须在独立干净工作区和不继承当前对话的全新任务中运行，仅靠提示词要求“不看 Gold”不构成充分隔离。

### 输入白名单

干净工作区在运行开始时只能包含：

- `paper.pdf`；
- `paper.txt`；
- 冻结后的通用 `BUILDER_PROTOCOL_V1.md`；
- 只列文件名、大小和哈希的输入清单。

### 明确禁止

- Gold、Gold 哈希、评分规则、讨论日志、当前或历史对话；
- 任何论文特定中文解读、提示、摘要或已有 Builder 输出；
- 外部网页、论文解读、作者材料及联网搜索；
- 从当前任务派生且继承上下文或共享答案文件的子 Agent 作为正式盲 Builder。

### 执行顺序

1. 创建独立干净目录并复制白名单文件；
2. 核对文件数、文件名、大小和 SHA-256，执行禁用文件名与内容提示扫描；
3. 新建不继承当前对话的任务，以干净目录作为唯一工作区；
4. Builder 只在该目录读取和写入；
5. 运行结束后先冻结 `BUILDER_OUTPUT.md`、`BUILD_TRACE.md` 和运行清单并计算哈希；
6. 冻结完成后，才将结果带回当前研究任务与 Gold 对照。

输入清单固定命名为 `INPUT_MANIFEST.sha256`，列出 `paper.pdf`、`paper.txt` 和 `BUILDER_PROTOCOL_V1.md` 的哈希。清单本身不包含论文内容或评价提示。

### 隔离声明

该设计防止显式 Gold 和讨论记录泄漏，但不能证明模型预训练中从未见过论文；潜在预训练记忆继续作为 Pilot 限制记录。

## 8. 已确认：单次预注册主运行与失败重试

Pilot 01 只接受一次预注册的完整有效主运行，不因输出质量不理想而重新生成或挑选更好的结果。

### 运行前必须固定

- 模型标识与推理配置；
- Builder 协议版本与哈希；
- 输入白名单与各文件哈希；
- 三轮主流程、最多两次定向修正和输出要求；
- 技术失败判据与重试上限。

### 允许技术重试的情况

- 输入文件无法读取或损坏；
- 服务错误、任务意外中断或工具不可用；
- 输出文件未写入、损坏或无法校验；
- 有可观察证据表明协议没有完整执行。

### 禁止重试的情况

- 理解结果不够好；
- Gold 命中率可能较低；
- 主干判断、关系或 GenerativePlan 与研究者预期不同；
- 希望更换模型或提示以取得更漂亮的结果。

发生允许的技术失败时，最多重试一次；必须在运行清单中记录失败时间、可观察错误、已产生文件及处置。不得查看 Gold 后决定是否重试。正式多次重复与多模型比较推迟到方法跑通后的实验阶段。

### 冻结输出包

- `BUILDER_OUTPUT.md`：七部分结构化理解结果；
- `BUILD_TRACE.md`：轻量关键构建与修订事件；
- `RUN_MANIFEST.md`：实际模型、配置、时间、协议与输入哈希、停止状态和重试记录；
- `OUTPUTS.sha256`：前三个文件的 SHA-256 校验值。

`OUTPUTS.sha256` 生成后，前三个文件不得原位修改；发现错误时保留原输出并创建带新版本号的更正文件。

## 9. 已确认：模型与推理配置

- **模型**：`gpt-5.6-sol`。
- **推理档位**：`xhigh`。
- **运行方式**：单一 Builder、标准模式；不启用多 Agent，不把不同阶段分派给不同模型。
- **模型不可用**：停止并报告，不得静默切换到其他模型、档位或模式。
- **结果选择**：只接受第一次完整有效主运行，不生成多个候选再挑选。

运行清单必须记录请求模型、实际显示模型、推理档位、任务开始与结束时间、协议哈希、输入哈希、技术失败和重试情况。若应用无法显示精确模型快照，只记录可观察到的模型标识并把这一点列为复现限制，不猜测底层版本。
