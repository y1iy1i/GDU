# GDU — Generative Document Understanding

GDU（Generative Document Understanding，生成式文档理解单元）是一个面向长文档理解与知识持久化的研究项目。

它希望解决的问题不是“怎样把文档切得更碎”，而是：

> 怎样让系统逐步形成、核验、修正并保存对整份文档的整体理解，同时让重要判断能够回到原文证据。

## 项目定位

普通 Chunk、向量检索和 RAG 主要帮助系统找到与当前问题相关的片段；GDU 进一步研究如何在查询发生之前，构建一份可复用的文档理解表示。

GDU 研究由三个相互分离的部分组成：

- **Builder**：离线阅读文档，形成局部理解、跨部分关系和整体解释，并通过回查修正早期判断。
- **GDU**：冻结后的持久知识表示，保存理解结果及其证据边界。
- **Reader**：在查询阶段读取 GDU；它是后续实验中的测量工具，不负责偷偷改写已冻结的理解。

## 核心思路

当前研究采用“四层主干＋贯穿机制”：

1. **原文与结构**：确认来源版本、物理结构和原文坐标。
2. **局部理解**：形成锚定原文的语义单元，区分局部内容与局部功能。
3. **关系理解**：恢复支持、限制、依赖、冲突和回应等跨部分关系。
4. **整体生成理解**：形成对文档目标、核心意义、内容选择、组织方式和结论边界的整体理解。

证据接地、不确定性与多解释、全局—局部双向修正贯穿四层。

Builder 不是一次性总结器。它先扫描结构并形成局部判断，再提出暂定的整体理解；后续证据可以触发定向回查，修改前面的判断、关系和整体计划。关键修订需记录触发证据、修改理由和影响范围。

## 与相关技术的关系

| 技术 | 主要职责 |
|---|---|
| PDF 解析 / MinerU 类工具 | 恢复文字、表格、公式和版面对象 |
| Chunk | 提供适合模型处理的计算窗口 |
| PageIndex 类方法 | 建立层级导航，帮助定位相关章节 |
| RAG | 针对当前问题检索相关片段 |
| GDU Builder | 逐步形成、挑战、修正并冻结整份文档的理解 |

这些技术可以成为 GDU Builder 的下层组件或实验基线，并不必然互相排斥。

## 当前研究状态

项目目前处于**研究原型阶段**，尚未发布正式 Schema、Builder 实现或可安装软件包。

已经完成的工作：

- 冻结了一套通用的渐进式盲 Builder 协议；
- 在两篇英文 NLP 实证论文上完成独立盲构建与人工 Gold 对照；
- 在一份 237 页中文上市公司年度报告上完成跨领域、跨语言、跨长度验证；
- 三轮运行均形成来源身份、物理结构、语义单元、原子判断、关系、五问式整体计划和证据索引；
- 验证了后期证据修正早期理解、保留来源内部冲突和限制过度推断的可行性。

最新的长年报试验中，15 项预先冻结的 Gold 得到 10 项完整命中、5 项部分命中、0 项完全遗漏；未发现高影响无依据结论或高影响证据错配。该结果属于初步质性证据，不代表 GDU 已经优于 PageIndex、Chunk、RAG 或其他知识存储体系。

## 当前不作出的主张

本项目目前**不声称**：

- GDU 已在公平实验中优于现有检索或知识库方法；
- 当前 Markdown Builder 输出就是最终 GDU 产品格式；
- 强模型上的可行性结果可以直接推广到小模型；
- 一个固定层数或字段集合适用于所有文档；
- 无保留的模型输出可以代替人工评价或原文证据。

## 最小表示方向

三轮实验正在支持一个候选的单文档表示：

- `manifest`
- `physical_structure`
- `semantic_units`
- `assertions`
- `relations`
- `generative_plan`
- `evidence`

这七项是规范化存储分工，不代表七层理解架构。最终 Schema 仍需通过三轮产物反推、复杂度审计和后续对照实验后冻结。

## 研究路线

1. 审计三轮 Builder 产物，反推最小 GDU Schema；
2. 固定 Reader 与评价任务；
3. 与全文提示、普通 Chunk/RAG、PageIndex 类方法做公平对照；
4. 对局部功能、跨部分关系、整体计划和定向回查做消融实验；
5. 实现面向大文档的分段读取、外部工作记忆和证据回查 Builder；
6. 研究“小模型＋渐进式 Builder”能否以更低成本接近强模型的理解质量。

## 复现与开放计划

后续公开内容预计包括：

- 研究规格和术语定义；
- 最小 Schema 与示例 GDU；
- Builder 协议、运行记录格式和验证器；
- 在许可允许范围内发布的实验输入清单、哈希和评价结果；
- 基线、消融、成本与错误分析。

在正式发布前，仓库中的设计均应视为研究中的候选方案，而不是稳定 API。
