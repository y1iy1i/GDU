# 生成式文档理解单元（GDU）研究规格 v0.1

> 状态：研究规格 / 可进入最小实现  
> 日期：2026-08-14  
> 上游依据：`09_generative_document_unit_full_report.md`、`NEXT_PROJECT_HANDOFF.md`  
> 适用阶段：单文档、单领域试点  
> 本版本不代表实验结论

## 1. 本版本冻结的研究判断

### 1.1 研究对象

生成式文档理解单元（Generative Document Understanding Unit，GDU）不是摘要、目录树或向量索引的别名。它是一个文档级、可追溯、有不确定性记录的知识对象：

\[
GDU = Source + Claims + DocumentModel + Relations + Provenance + Views
\]

- `Source`：不可由模型生成内容替代的原始文档定位层；
- `Claims`：可独立验证的事实、解释、功能和关系主张；
- `DocumentModel`：对目的、主体思想、受众、约束、结构和体裁偏差的显式建模；
- `Relations`：章节、主张和证据之间可审查的有向关系；
- `Provenance`：从每项知识回到原始页码、Chunk或结构信号的路径；
- `Views`：从同一内核派生的人类阅读视图与Agent读取视图。

“生成式”指该表示能够支持结构解释、缺失预测、反事实调整和受约束重建；不表示生成文本可以充当原始证据。

### 1.2 核心研究命题

在相同原文、模型、问题、答案上下文和成本口径下，包含文档目的、章节功能与跨章节关系的GDU，应在高阶理解任务上优于等Token摘要和检索基线，同时不显著损害局部事实问答和证据忠实度。

该命题若不能通过预先定义的任务和门槛，将被否定或收缩适用范围。

### 1.3 人类与Agent共同可读的含义

共同可读不等于把JSON直接展示给人类，也不等于为人类和Agent维护两份独立知识。

本项目采用“一个内核、两种视图”：

```text
原始文档与Chunk
        ↓
GDU规范化内核（稳定ID、主张、关系、证据、不确定性）
        ├── Agent View：JSON、图遍历、检索入口、约束
        └── Human View：概览、结构地图、解释、证据卡、争议项
```

任何人类视图中的结论都必须引用内核ID；任何Agent视图中的高阶主张都必须能够展开为人类可审查的解释与证据。视图是派生物，不是第二事实源。

## 2. 明确不做什么

v0.1不承诺：

- 恢复作者唯一真实心理；
- 用GDU替代PDF、表格、Chunk或精确检索；
- 仅凭流畅重写证明理解；
- 一开始覆盖小说、论文、财报、合同等所有领域；
- 训练多Agent或强化学习系统；
- 重新生成全部PageIndex缓存；
- 用反复调参的30题开发集支持普适结论；
- 在没有人工授权时调用付费API。

首轮领域限定为已有证据资产最完整的金融报告。跨领域普适性保留为后续假设，而不是v0.1既成事实。

## 3. GDU规范化内核

机器格式由[`schemas/gdu-v0.1.schema.json`](../../schemas/gdu-v0.1.schema.json)定义。本节说明语义约束；JSON Schema只能验证其中一部分。

### 3.1 `manifest`：身份与版本

必须包含：

- `gdu_id`、`schema_version`和GDU版本；
- 原文`document_id`、内容哈希、标题、文档类型、语言和页数；
- 构建时间、构建方法、模型与提示版本；
- 上游Chunk集和PageIndex树的版本或哈希。

同一原文在不同构建方法下产生不同`gdu_id`。原文哈希变化时必须新建版本，不能静默覆盖。

### 3.2 `source_units`：原文锚点

`source_unit`是GDU中最小可引用原文单元。v0.1允许：

- `chunk`：正文片段；
- `table`：表格或表格区域；
- `figure`：图形及说明；
- `heading`：显式标题；
- `page_region`：无法可靠解析时的页内区域。

每个单元必须至少记录页码；可用时还应记录字符范围、表格单元格、边界框、Chunk ID和原文文本。页码统一使用从1开始的PDF物理页码。

`source_units`不复制或重排Embedding矩阵。旧项目的`chunks.jsonl`与`embeddings.npy`仍保持逐行对应，GDU只通过稳定`chunk_id`引用它们。

### 3.3 `claims`：可验证知识主张

每个主张必须足够原子化，使审查者能够判断证据是否支持它。主张分为：

| `claim_type` | 含义 | 示例 |
|---|---|---|
| `fact` | 文档明确陈述的事实、数字或限定条件 | 某项收入同比下降 |
| `main_idea` | 文档或部分的核心信息 | 管理层将利润变化归因于成本上升 |
| `purpose` | 文档或部分试图完成的沟通功能 | 解释本期经营变化 |
| `section_function` | 某部分在全文中的作用 | 限定前文结论的适用范围 |
| `relation` | 两项内容的因果、证据、对比等关系 | 风险因素限制预测的确定性 |
| `constraint` | 法规、体裁、事实、表达或受众约束 | 必须披露特定财务口径 |
| `genre_deviation` | 本文相对体裁惯例的特殊选择 | 异常强调某一新风险 |

`epistemic_status`必须使用以下四级之一：

1. `explicit`：原文直接表达；
2. `entailed`：由一项或多项原文证据较确定地推出；
3. `inferred`：合理解释，但存在其他可行解释；
4. `hypothesis`：需要验证的开放假设。

置信度不能替代该分类。`confidence`用于同一级内部的校准；`rationale`说明推断路径；存在多解时用`alternative_claim_ids`保留竞争解释。

### 3.4 `evidence_links`：证据账本

证据边把`claim_id`连接到一个或多个`source_unit_id`。每条边必须记录：

- 证据作用：`supports`、`contradicts`、`qualifies`或`contextualizes`；
- 支持方式：`direct`、`multi_source_inference`、`structural_signal`或`genre_prior`；
- 是否足以单独支持该主张；
- 人类可读的简短说明；
- 可选的审查状态。

`genre_prior`只能解释候选结构或功能，不能单独支持`fact`主张。模型生成的摘要、重写或此前答案不得登记为原始证据。

### 3.5 `document_model`：逆向写作模型

文档模型包含：

- `purpose_claim_ids`：一个或多个受证据支持的潜在目的；
- `main_idea_claim_ids`：主体思想；
- `audience`：目标读者与预设知识；
- `constraint_claim_ids`：制度、事实、格式和表达约束；
- `genre_prior`：文档类型的一般惯例及来源说明；
- `document_specific_choices`：本文遵循、偏离或重新组合惯例的地方；
- `sections`：文档结构与每部分功能；
- `relations`：跨章节、主张或证据关系。

目的允许并列、多层和冲突。不得强迫生成单一“作者意图”。

### 3.6 `sections`：结构与功能

每个章节节点包含标题、父节点、顺序、覆盖的`source_unit_ids`、内容摘要和`function_claim_ids`。章节节点既可以来自原文标题，也可以是系统恢复的潜在段落。

系统恢复的章节必须标记`boundary_origin=inferred`，并提供边界依据。PageIndex节点可作为结构候选，但其摘要不是事实证据。

### 3.7 `relations`：图而不只是树

v0.1使用有类型、有方向的图。允许的最小关系集合：

- `elaborates`：展开；
- `supports`：论据支持；
- `qualifies`：限定；
- `contrasts`：对比；
- `causes`：原因指向结果；
- `motivates`：动机或理由；
- `defines`：定义；
- `uses`：后文使用前文概念、数据或规则；
- `precedes`：顺序或前置依赖；
- `resolves`：回应问题、伏笔或开放项；
- `exemplifies`：举例；
- `same_topic`：仅主题相关，不能冒充更强逻辑关系。

边必须指向存在的章节或主张，并用证据链接或明确的推断说明支撑。树用于层级，图用于跨层和跨章节关系。

### 3.8 `views`：派生视图声明

`views`只登记可重新生成的派生物及其输入ID：

- `agent_view`：面向程序的裁剪、查询入口和图邻域；
- `human_view`：面向阅读的概览与证据卡；
- `reconstruction_plan`：受约束重建使用的大纲与必保留事实；
- `question_view`：针对某问题生成的临时子图。

视图中新增的解释若要持久化，必须回写为新主张并经过证据与不确定性检查。

## 4. 必须满足的语义不变量

以下条件是实现门槛，不满足时GDU无效：

1. 每个ID在一个GDU版本内唯一且稳定。
2. 每个`source_unit`都能解析到现存原文与1-based物理页码。
3. 每个`explicit`或`entailed`主张至少有一条非`genre_prior`证据边。
4. 每个`fact`主张必须有原文证据，不能只依赖结构信号或体裁先验。
5. `inferred`和`hypothesis`主张必须有`rationale`，并显式呈现为推断。
6. 所有章节功能、目的和跨章节关系都必须能展开为证据或结构信号。
7. 生成内容不能成为其自身或上游主张的证据，避免循环出处。
8. 人类视图和Agent视图引用同一内核ID，不维护独立事实副本。
9. 原文、Chunk或树版本变化后，旧证据定位不得静默复用。
10. 删除或过滤Chunk时，旧Embedding行序对应关系必须保持或生成新的成对版本。

JSON Schema负责字段、类型、枚举和引用格式；上述跨对象引用、证据充分性和循环检测需要独立验证器。

## 5. 查询与阅读协议

GDU不是所有问题的强制复杂路径。路由首先判断任务类型。

### 5.1 局部事实路径

```text
问题 → BM25/Dense/Hybrid候选 → 原文证据 → 答案与页码
```

GDU只提供文档范围、术语消歧和限定条件提示，不应扩大无关上下文。

### 5.2 高阶理解路径

```text
问题
→ 定位相关purpose/function/relation主张
→ 展开为相关章节与证据子图
→ 回到原始Chunk、表格和页码核验
→ 输出“原文事实 + 综合推断 + 不确定性”
```

### 5.3 回答格式底线

高阶回答至少区分：

- `document_states`：原文明确表达；
- `supported_synthesis`：多处证据共同支持的综合；
- `interpretation`：可争议解释；
- `unknown`：文档不足以判断。

任何事实数字必须引用原始页码。目的和功能解释也要显示支撑证据与备选解释，不能用肯定语气掩盖推断。

## 6. 人类阅读视图 v0.1

人类视图固定为六个区域：

1. **一分钟概览**：文档是什么、为何存在、主体思想、适用范围；
2. **结构地图**：章节顺序、功能和关键跨章节边；
3. **核心主张**：按事实、综合和解释分组；
4. **阅读路径**：针对常见目标给出推荐章节和理由；
5. **证据卡**：原文摘录、页码、表格位置和支持强度；
6. **不确定性与争议**：备选解释、缺失证据和待人工审查项。

可读性不是单纯语言流畅度。评测关注：找到结论所需时间、定位证据所需时间、错误发现率、主观认知负担和人机结论一致性。

## 7. 可证伪评价任务

### T0：结构与出处有效性

- Schema通过率；
- ID引用完整率；
- 页码和Chunk定位可解析率；
- 循环出处数量；
- 过期来源检测率。

### T1：局部事实问答

沿用FinanceBench的Hit@K、Page Recall、MRR、nDCG、答案F1和数值匹配。目标是证明GDU没有牺牲精确证据能力，而不是要求它在所有事实题上胜出。

### T2：跨章节证据组合

问题必须需要至少两个相距较远的证据单元。评价：答案正确率、证据集合Precision/Recall/F1、遗漏限定条件率和无依据综合率。

### T3：结构恢复

- 隐去标题后的章节边界恢复；
- 章节顺序恢复；
- 父子结构恢复；
- 标题或功能标签生成。

评价使用边界F1、父子边F1、顺序相关性和人工可接受率。标题文字相似度只能作为辅助指标。

### T4：章节功能解释

给定章节，回答它对全文目的做了什么、删除后损害什么。评价由双人标注的允许答案集、证据充分性和备选解释覆盖度共同构成。

### T5：关系识别

识别跨章节的支持、限定、对比、因果、定义使用等关系。评价关系端点F1、类型F1、方向准确率和证据充分性。

### T6：缺失预测

隐藏一个章节，预测缺失部分需要完成的功能、需要覆盖的事实类型和合理位置。先评功能与约束，再评文本；不能用与原文的表面相似度单独判定。

### T7：反事实调整

改变受众、目的或关键证据，要求指出哪些章节、主张和结论必须变化，哪些必须保持。评价变化集合F1、约束遵循和未授权事实改写率。

### T8：受约束重建

从GDU重建功能等价的短化文档。评价：目的、结构、核心主张、限定条件、数字、关系与引用保持率，以及新增无依据主张率。流畅性独立报告，不并入事实忠实度。

### T9：共同可读性

让人类和Agent分别完成同一组理解与查证任务：

- 人类：原文、等Token摘要、GDU人类视图；
- Agent：Chunk、PageIndex、摘要、GDU Agent视图。

测量正确率、完成时间、证据定位时间、错误发现率和信心校准。共同可读性的证据是两类使用者都获益且能落到同一证据，不是单侧偏好评分。

## 8. 公平对照与消融

### 8.1 必须保留的对照

- 原始Chunk + BM25；
- 原始Chunk + Dense；
- Chunk + Hybrid/RRF；
- PageIndex；
- PageIndex + Dense/Hybrid；
- PageIndex + Dense + LLM Rerank；
- 等Token普通全文摘要；
- 仅章节树/篇章结构表示；
- 完整GDU。

所有方法使用相同文档、问题、模型版本、最终回答上下文上限和证据评分规则。离线构建成本与在线查询成本分开。

### 8.2 关键消融

- GDU去掉目的与受众；
- 去掉章节功能；
- 去掉跨章节关系；
- 去掉体裁偏差，只保留通用模板；
- 去掉不确定性与备选解释；
- 去掉证据账本，只保留可读模型；
- 用等Token摘要替换完整GDU。

消融回答“收益来自哪一层”，而不是只寻找最高总分。

## 9. 首轮数据与标注设计

### 9.1 数据选择

先从46份完整缓存文档中按以下规则离线选取小样本：

- 按文档划分，不能让同一财报的问题进入不同集合；
- 覆盖短、中、长三档页数；
- 覆盖不同公司与报告年份；
- 不根据旧30题方法表现挑选文档；
- 首轮只做6至8份文档，用于验证Schema与标注可行性，不发布总体效果结论。

正式实验再冻结开发集与测试集；所有提示、关系枚举和阈值只能在开发集修改。

### 9.2 高阶问题来源

FinanceBench现有题主要验证事实证据，不能单独证明GDU。首轮新增问题须来自人工阅读，并满足：

- 在看系统输出前完成问题与参考答案；
- 标注必需证据、可选证据和反证；
- 标注问题类型与是否必须跨章节；
- 允许多个合理解释时记录允许集合和判定理由；
- 由第二位标注者独立审查。

模型可以提出候选问题，但不能同时生成未经人工审查的金标准并评价自己。

### 9.3 标注单元

每个高阶样本至少包含：

```text
question_id
document_id
task_type
question
reference_answer_set
required_source_unit_ids
optional_source_unit_ids
counterevidence_source_unit_ids
allowed_interpretations
disallowed_inferences
annotator_notes
review_status
```

## 10. 指标与成本口径

除原检索指标外，v0.1新增：

- `provenance_resolvability`：可成功解析到原文的证据引用比例；
- `claim_support_precision`：被判定有充分证据的持久化主张比例；
- `unsupported_claim_rate`：输出中无依据原子主张比例；
- `evidence_set_f1`：预测与金标准证据集合F1；
- `relation_f1`：端点和关系类型均正确的边F1；
- `constraint_preservation`：重建中保留的必需约束比例；
- `calibration_error`：置信度与人工正确率之间的误差；
- `human_verification_time`：人类验证一个答案及其依据的时间；
- `shared_understanding_agreement`：人类和Agent对结论、证据及不确定性分类的一致率。

成本至少报告：构建输入/输出Token、本地Embedding耗时、存储体积、查询Token、P50/P95延迟、API费用、每个正确高阶答案的成本，以及按100/1,000/10,000次查询摊销后的单题成本。

## 11. v0.1试点成功门槛

以下是预注册前的暂定工程门槛；在看到试点结果前可以经人工审查修改一次，冻结后不得追分调整：

1. Schema实例验证通过率100%；
2. 所有持久化证据引用均可解析到正确文档和页码；
3. 人工抽查的`fact`主张不允许以生成摘要或体裁先验作为唯一证据；
4. 相对最强检索基线，局部事实问答不能出现未经解释的明显退化；
5. 完整GDU在至少一类预先定义的高阶任务上优于等Token摘要和仅结构基线；
6. 去除证据账本后，忠实度或可审查性应显著下降，否则证据层的复杂度缺乏依据；
7. 人类使用GDU视图时，验证时间或错误发现率至少有一项优于普通摘要，且正确率不下降；
8. 所有收益都必须同时报告构建和查询成本。

v0.1是可行性试点，不以小样本显著性声称普适结论。正式阈值与置信区间在标注试点完成后预注册。

## 12. 最小实现切片

下一轮实现只包含：

## 13. 实现门（按顺序）

### Gate A：表示可行

- Schema和语义不变量可自动验证；
- 一份真实文档可完整表达；
- 人类视图与Agent视图能从同一内核重建；
- 所有证据引用可解析。

### Gate B：标注可行

- 两位标注者能独立使用关系和证据规范；
- 分歧可归因到明确类别；
- 允许答案集不会退化为“什么都算对”。

### Gate C：小样本实验可行

- 基线和GDU使用相同输入与上下文预算；
- 逐题结果、成本、错误类型完整保存；
- 至少观察到一个可复核的高阶收益或明确失败边界。

### Gate D：扩大验证

只有前三道门通过后，才扩大文档数量、调用付费API或引入第二领域。

## 14. 关键失败判据

出现以下任一现象时，应暂停扩展并修正或否定方案：

- GDU无法稳定区分原文事实与合理猜测；
- 高阶主张无法解析到具体证据或结构信号；
- 等Token摘要在所有高阶任务上与GDU相当或更好；
- GDU提升来自增加上下文或更强模型，而不是表示本身；
- 人类视图更流畅，但更难发现错误或定位原文；
- 同一文档重建结果随运行产生不可接受的结构漂移；
- 构建成本在合理查询量下无法摊销；
- 体裁先验持续覆盖本文特有内容。

## 15. 当前开放问题

以下问题保留到Schema实例和双人标注试点后决定：

1. `confidence`采用模型自报、校准分类器还是仅人工等级；
2. 关系集合是否需要金融领域专用子类型；
3. 表格证据以单元格、行、区域还是语义记录为最小单元；
4. 章节功能允许多少个并列标签；
5. 如何为多解目的和解释计算一致性；
6. Human View的最优信息密度；
7. 正式高阶题库使用金融文档自建集，还是引入QASPER等第二领域数据；
8. 何时从JSON文件存储迁移到图或关系数据库。

v0.1不需要数据库。先证明表示和评价有效，再选择存储技术。

## 16. 与现有研究的边界

- [Disco-RAG](https://aclanthology.org/2026.acl-long.189/)把Chunk内篇章树、跨Chunk修辞图和生成规划结合起来，支持“结构有助于跨片段聚合”；GDU额外要求文档目的、证据账本、不确定性和人机共读视图。
- [Beyond Chunking / DISRetrieval](https://aclanthology.org/2026.acl-long.829/)说明层级篇章组织可以优于任意切分，同时指出关系标签本身未必直接预测检索正确性；因此GDU必须通过消融验证关系语义的增量价值，不能默认图越复杂越好。
- [eRST](https://aclanthology.org/2025.cl-1.3/)支持使用可打破树结构、允许并发关系并带显式信号的篇章图；GDU采用“层级树 + 跨章节图”而非单一严格树。
- [Outline Generation](https://arxiv.org/abs/1905.10039)把章节边界和标题恢复形式化为结构化预测任务；GDU将其纳入结构恢复评价，但不把大纲等同于完整理解。
- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)表明长文本事实评价需要原子化主张；GDU据此采用原子`claims`，但证据范围限定为当前文档。
- [W3C PROV-O](https://www.w3.org/TR/prov-o/)提供实体、活动、Agent和派生链的稳定出处思想；GDU v0.1使用轻量文件表示，保留未来映射到标准出处模型的可能。
- [QASPER](https://aclanthology.org/2021.naacl-main.365/)提供跨论文内容的信息寻求问题与证据标注，可作为未来第二领域或高阶问答设计参考，但不在金融试点中直接混用结论。

## 17. v0.1结论

GDU的最小创新不在于生成更长的摘要，而在于建立一个可验证的文档模型：它把目的、结构、功能和跨章节关系表示为可争议的主张，把原文事实表示为可定位证据，并从同一内核生成Agent与人类各自适合的阅读视图。

下一步的正确动作是完成一份真实文档实例、语义验证器和两种视图，而不是立即扩大数据规模或优化模型。
