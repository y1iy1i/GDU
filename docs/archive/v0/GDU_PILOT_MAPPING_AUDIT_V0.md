## 1. “无损”的含义

本审计检查旧实验中的有意义信息能否进入新逻辑结构，并保持来源、认识论身份、边界、关系、不确定性和修订历史。它不要求旧表格逐字段原样复制，也不把排版、重复索引或旧分类混用视为必须保留的信息。

## 4. C-001—C-009 是否造成信息损失

- C-001 删除 unit 侧普通 `assertion_refs`：不丢失；可由 assertion 的归属反向生成。主要/次要功能引用仍保留。
- C-002 统一 `rationale`：不丢失；旧“分析理由”进入公共理由，基础判断另存引用。
- C-003 简化解释组：不丢失；成员并集保存一次，当前倾向由可选 `preferred_ref` 表达。
- C-004 删除单文档 Evidence `source_ref`：不丢失；三轮均为单一权威 PDF，来源由 Manifest 唯一确定。
- C-005 relation 删除 `derived`：不丢失；Pilot 02/03 的算术先形成 derived assertion，再连接其他对象。
- C-006 保留 `assessment_complete`：能保存“未检查”与“已检查仍不确定”的差异。
- C-007 保留 relation 的说明和理由：能分别承接旧关系的语义与接地依据。
- C-008 条件式 unit 归属：能承接局部、跨章节及全文级判断；function 判断对象保持唯一。
- C-009 relation 来源条件：能区分来源明确关系与 Builder 综合关系，三轮均有实例。

## 5. 必须规范化、不能机械照抄的地方

1. 旧输出存在 `内容/限制`、`功能/限制` 等混合类别；迁移时必须拆成多个单一 kind assertions，并用 `limits`、`supports` 等关系连接。
2. 旧输出把“作者明确 + Builder 限定”写在同一行；必须拆分来源判断与分析边界，分别赋予 epistemic origin。
3. 旧语义单元的局部功能多为自由文本；需建立一个主要、最多两个次要 function assertions，并明确目标单元。
4. 旧冻结输出没有逐对象显式填写 `assessment_complete` 和四值 `evidence_status`；迁移时需依据证据与 Gold 对照补做一次公开状态归一，不能一律自动标记为 `supported`。
5. 旧构建记录的事件名称不完全一致；只迁移会改变对象、证明检查完成、记录技术影响或冻结产物的事件，不复制过程噪声。

以上是规范化工作，不表示新结构缺少承载位置。

## 6. 审计结论

- **表示能力：通过。** 三轮 Pilot 的重要信息都能进入精简后的七块和独立构建日志。
- **减重安全性：通过。** C-001—C-005 删除的均为重复事实源或职责错误的组合，没有删除独立语义。
- **自动迁移：未通过，也未作为当前目标。** 旧类别拆分、功能判断建立和证据状态归一仍需要人工审查或未来的受控迁移器。
- **领域专用扩展：暂无需要。** 两篇 NLP 论文和一份长篇中文年报都未暴露必须新增顶层块或 Profile 的缺口。

下一步应先写一个极小的人类可读实例，验证这些规则能否在真实对象上同时落地；通过后再讨论 JSON Schema。
