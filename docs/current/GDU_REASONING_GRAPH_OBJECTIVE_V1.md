# GDU 可审计推理图目标 v1

> 日期：2026-08-20  
> 状态：下一阶段实验约束；不修改既有冻结基线

## 1. 研究目标

GDU 的目标不是把文档切成更精致的 Chunk，而是把文档转换为一张可查询、可验证、可修订的外部推理图：

```text
用户问题 → 判断节点检索 → 关系路径 → 限制/冲突检查 → 证据锚点回查 → 答案
```

图中的判断与关系是主要知识单位。原始 PDF 和证据锚点是权威依据，但不作为查询阶段的主要检索单位。固定长度 Chunk 只允许作为 Builder 读取长文档时的临时窗口，不进入最终知识表示。

这里的“推理路径”是可以被检查的外部理由链，不保存或要求模型披露隐含思维过程。

## 2. 四层主干

1. **证据层**：原文位置、原文内容、载体类型、文档版本和哈希。
2. **判断层**：单一、可判真假的陈述，包含对象、时间、口径、状态和置信度。
3. **关系层**：首版只使用 `supports`、`limits`、`conflicts`、`composes`。
4. **路径层**：针对问题形成的临时子图，必须列出结论、经过的节点、限制及证据。

层数可以随文档复杂度调整，但上述四层是默认主干。

## 3. “正确”的操作定义

一张图只有同时满足以下条件，才进入 Gold GDU：

- **证据正确**：数字、单位、正负号、表头和页码可由原文复核；
- **语义不过界**：事实、解释、计划和风险不互相冒充；
- **范围明确**：对象、期间、合并/母公司等口径不被省略；
- **关系成立**：边的方向和类型有可说明的依据；
- **分歧保留**：不同范围的陈述不被误判为矛盾，有依据的备选解释不被删除；
- **版本可追踪**：新证据只产生新版本，不静默覆盖旧判断。

“正确”不是宣称知识库永不出错，而是错误可以被定位、复核、修订和追责。

## 4. 查询时错误发现

问答阶段必须在生成答案前运行路径审计。首版检测四类问题：

| 问题 | 判断条件 | 系统行为 |
|---|---|---|
| 断链 | 找到相关节点，但无法组成支持结论的路径 | 不强答，报告缺失节点或关系 |
| 显式矛盾 | 同一路径包含仍有效的 `conflicts` 节点 | 并列冲突和适用范围，降低答案确定性 |
| 证据不一致 | 节点中的数字、符号或口径与证据解析结果不符 | 阻止该节点参与正式答案，触发证据回查 |
| 版本冲突 | 路径同时使用已失效节点和其后继版本 | 只使用当前有效版本，并报告变更 |

## 5. 有边界的自修复

自修复分为五步：

```text
检测异常 → 回到原文证据 → 生成候选修复 → 独立验证 → 建立新版本
```

系统可以自动完成检测、回查和修复提案，但不得直接覆盖正式知识：

- 证据充分且通过确定性规则时，候选可标记为 `machine_verified`；
- 需要语义判断时，候选标记为 `review_required`；
- 修复被批准后，旧节点改为 `superseded`，新节点获得新 ID；
- 所有引用旧节点的路径进入待重算队列；
- 原始错误节点继续保留，用于审计和 Builder 回归测试。

自修复不是“模型重新回答一次”，而是对图中明确对象执行有证据、有版本的补丁。

## 6. 分离两个实验变量

### 实验 A：图是否有价值

使用人工校验的 Gold GDU，对比 Raw Chunk，重点测试：

- 多跳问题；
- 严格上下文预算；
- 矛盾和范围边界；
- 单节点更新后的影响传播；
- 答案到原文的完整追溯。

### 实验 B：Builder 是否能建对图

自动 Builder 不读取 Gold，生成候选图后与 Gold GDU 对比：

- 节点召回率和准确率；
- 关系准确率；
- 证据锚定准确率；
- 高影响错误率；
- 自动检测和修复成功率。

只有先证明实验 A 中正确的图具有净优势，才值得继续投入实验 B 的自动化。

## 7. 当前阶段通过条件

本阶段不以普通单事实问答分数作为主要结论。原型至少需要证明：

1. 一个错误节点会在回答前被拦截，而不是沿关系继续传播；
2. 系统能给出指向原文的具体修复提案；
3. 修复不覆盖历史记录；
4. 修复后受影响路径能够重算；
5. 无充分证据时系统选择保留分歧或回答不足。
