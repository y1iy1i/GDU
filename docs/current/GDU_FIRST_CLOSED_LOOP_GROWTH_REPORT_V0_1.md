# GDU 第一次提问驱动正式生长闭环报告 v0.1

## 实验目标

验证以下完整过程是否能够真正运行：

```text
用户问题
→ 查询规划
→ 发现正式图缺口
→ 邻域扩散与原文回查
→ 候选隔离
→ 数值、证据、Context、因果措辞和边界校验
→ 生成新版本图
→ 重新回答原问题
```

本轮使用问题：“哪项投资活动导致全年现金减少？”

## 生长前

v0.1 图缺少以下两个 Atom：

- `investment_cash_change_driver`；
- `investment_is_sole_cash_decrease_cause`。

查询规划器返回 `gap`，没有利用相近词语猜出答案。

## 候选提升门

候选必须同时通过五项检查：

1. Context 为 2025 年合并口径；
2. 第 72—73 页跨页投资现金流表精确对账；
3. 经营、投资、筹资现金流和汇率影响合计与全年现金变化一致；
4. “主要系”只保留为报告对同比变化的原因说明，不扩大成唯一因果；
5. 新结论必须明确投资活动不能单独解释全部现金变化。

数字核对结果：

| 检查 | 结果（元） |
|---|---:|
| 投资现金流入 | 69,525,306.42 |
| 投资现金流出 | 306,155,126.21 |
| 计算的投资现金流净额 | -236,629,819.79 |
| 报告的投资现金流净额 | -236,629,819.79 |
| 计算的全年现金变化 | -187,884,922.38 |
| 报告的全年现金变化 | -187,884,922.38 |
| 残差 | **0.00** |

## 正式提升结果

提升过程没有修改 v0.1，而是生成 `gdu-logic-real-slice-v0.2`：

- 信息节点：34 个；
- 方案节点：18 个；
- 新增证据页：15、72、73；
- 版本事件：`GROWTH-2025-INVEST-001`；
- 版本记录包含父格式、候选内容哈希、新增节点列表和记录时间。

新增论证包括：

- 投资现金流入减流出的严格计算；
- 计算值与报告值的严格匹配；
- 投资净流出作为现金减少组成部分的桥接结论；
- 四类现金变动到全年现金变化的严格闭合；
- “投资是唯一原因”的可废止经验推断；
- “其他现金流组成部分非零”的严格反证及规则阻断。

## 生长后重新回答

同一个问题重新规划后由 `gap` 变为 `ready`。系统选择：

> 投资活动净流出 236,629,819.79 元，是全年现金减少的重要组成部分。投资活动净流出不是全年现金减少的唯一组成部分；经营、筹资现金流和汇率影响也必须计入。

“投资活动是全年现金减少的唯一原因”被标记为 `rejected`，不能进入答案。

## 安全性实验

### 候选篡改

将投资现金流出从 306,155,126.21 元改为 300,000,000.00 元后，候选无法通过投资现金流算术核对，提升操作被拒绝。

### 提升后失效传播

模拟投资流出明细失效后：

- 投资净额计算失效；
- 计算值匹配失效；
- 新增投资解释失效；
- 原文已经报告的全年现金减少事实仍然有效。

局部重算与全量重算结果一致。

### 独立重放

使用同一份 v0.1、同一候选、同一事件 ID 和记录时间，从零重新生成 v0.2。重放文件与正式 v0.2 逐字节一致，二者 SHA-256 均为：

`6b190760acc1e1a88eb27de5d1868fd98745b05218fe49505c6e2fdce515e709`

## 阶段结论

本轮首次实现了可运行的“提问触发数据库生长”闭环。它不是让模型直接改库，而是让查询发现缺口、让原文检索提出候选、让确定性验证门决定是否生成新版本。

因此目前可以更明确地说：GDU 已经具有受约束的生长能力，而不只是静态知识图或按照预设图回答问题。

当前仍然只验证了一次人工可核对的财务生长事件。独立重放已经通过；下一步应选择第二种非财务逻辑缺口，防止方法只适用于算术表格。
