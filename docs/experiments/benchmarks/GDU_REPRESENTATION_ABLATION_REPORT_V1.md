## 5. 按预注册规则作出的删除判断

### 顶层章节元数据

V1 没有超过 V0，总分反而低 1 分。该差异可能来自回答波动，但没有证据表明仅增加章节名能改善本组问题。章节信息可以保留为廉价检索元数据，不应被宣称为语义核心。

### 判断节点

V2 以约 2.6% 的原文字符规模取得与 V0 相同的总分，并在 Q3–Q6 上高 1 分。它保留了相向订金流量和分红冲突，是当前成本—效果最好的常驻表示候选。

### 显式关系图

V3 相比 V2 增加约 38% 字符，但总分仍为 8，关系/限制/冲突小计反而由 5 降为 4。按照预注册规则，显式关系没有达到“至少提高 2 分或修复高影响边界”的核心保留条件。

这不证明关系永远无用。当前判断是：**关系不必全部预先生成并永久保存**。可在复杂查询时并行计算，或把高价值关系作为可重建缓存。

### 完整 GDU

V4 比 V2 总分高 1，但 Q3–Q6 小计相同。按照预注册规则，语义单元、完整物理结构和 GenerativePlan 只能记为可选功能，尚不能进入最小查询核心。

## 6. 最小有效 GDU 候选

当前候选只保留两张主表。

### 判断节点表

```json
{

  "role": "limitation",
  "epistemic_source": "builder_analysis",
  "evidence_refs": ["E-018", "E-021"],

```

### 证据表

```json
{
  "id": "E-021",
  "page": 188,
  "locator": "physical-page:188",
  "text": "由程序从权威 PDF 绑定的完整片段",
  "sha256": "..."

```

章节、时间戳和版本状态作为字段；关系边作为可选派生表：

```json
{"from": "A-025", "type": "limits", "to": "A-007"}
```

关系候选可以按章节对、问题相关节点对并行计算，最后执行一次全局去重与冲突检查。

## 7. 当前架构结论

GDU 不应继续以“完整六阶段产物全部常驻”的方向扩张。六个 CP 可以保留为研究和质量控制流程，但运行时表示应收缩为：

> **可追溯的判断节点＋确定性证据；关系按需生成或缓存。**

下一次研究应在新文档上比较 V0、V2 与按需关系版本。若 V2 的关系/冲突优势不能复现，则 GDU 应进一步退化为带认识论标签的压缩型 Chunk；若能复现，再为最小 Builder 实现节点发现与证据绑定。
