# GDU 第三次规范性文档生长报告 V0.1

## 研究问题

第三个领域选用现行强制性国家标准 `GB 45438-2025 网络安全技术 人工智能生成合成内容标识方法`。该标准于2025年2月28日发布，2025年9月1日实施，实验时状态为现行。权威状态来源见[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F32EA2A561F1886CD8D606513512D547&refer=outter)。

冻结场景问题为：

> 一个AI生成视频的显式标识只在开头出现1秒，文字高度为画面最短边的5%，文件元数据按附录E完整填写。这个视频是否完全符合GB 45438-2025？

它要求 GDU 同时处理三种状态：持续时间违规，文字高度合格，元数据合格。实验的关键不是找到单个数值，而是避免把“局部合格”误推为“整体合格”。

## 理论对齐

[OASIS LegalRuleML 1.0](https://docs.oasis-open.org/legalruleml/legalruleml-core-spec/v1.0/os/legalruleml-core-spec-v1.0-os.html) 区分事实陈述、规定性规则、义务、许可、禁止和违规。其中一个重要原则是：“存在义务”和“义务未被满足”可以同时成立，违规不等于规则本身发生逻辑矛盾。输入/输出逻辑则将条件事实与规范性输出分开，用于表示条件义务，见 Makinson 和 van der Torre 的 [Constraints for Input/Output Logics](https://icr.uni.lu/leonvandertorre/papers/jpl01.pdf)。

本次没有声称已实现完整的 LegalRuleML 或义务逻辑。实验只做最小对齐：

- 条款 Claim 增加 `normative_force=obligation`、`bearer` 和结构化 `constraint`；
- 场景事实仍是普通 Claim；
- 义务与事实通过严格检查规则产生 `violation` 或 `satisfied`；
- 违规 Claim 不攻击义务 Claim，只攻击错误的整体合规结论。

## 生长闭环

1. v0.1 只保存标准适用范围和冻结场景事实；
2. 查询规划器发现缺少整体合规结论与限定命题；
3. 原文回查锁定物理第7页第5.4条、第8页第6.1条和第17页规范性附录E；
4. 候选先进入隔离区，通过页面、规范力、“应/可”区分、数值门槛和附录追溯五道领域门；
5. 通用晋升事务层写入 v0.2，生长事件为 `GROWTH-GB45438-VIDEO-001`；
6. 相同问题从 `gap` 变为 `ready`。

## 结果

GDU 生成的可审计结论为：

> 该视频不完全符合GB 45438-2025：显式标识只持续1秒，违反第5.4条不应少于2秒的要求。文字高度和元数据合格只能证明局部满足，不能抵消显式标识持续时间的违规。

具体表现：

- 义务和违规均被接受，二者不构成相互攻击；
- “有标识且元数据完整，所以整体合规”的可废止启发式被拒绝；
- 答案追溯到标准第5、7、8、17物理页和冻结场景文件；
- 删除持续时间义务后，整体结论失效，查询重新进入 `gap`；
- 局部重算与全量重算结果相同；
- 全仓回归为 `217 passed, 5 skipped`。

## 第三领域接入成本

这是本次实验最重要的测量：

| 部分 | 修改量 | 结论 |
|---|---:|---|
| 核心逻辑 `logic_v01.py` | 0行 | 三层逻辑主干可复用 |
| 答案生成 `answer_v01.py` | 0行 | 可审计答案接口可复用 |
| 通用晋升 `promotion_v01.py` | 0行 | 生长事务框架可复用 |
| 查询规划 | +17/-1行 | 需新增规范问题语义，并修复标准编号年份误判 |
| 领域生长插件 | 276行 | 义务标注、数值检查和节点模板仍是主要成本 |
| 领域测试 | 172行 | 覆盖语义、阻错、追溯、失效重算和确定性重放 |

因此，通用框架确实降低了“安全写入和逻辑执行”的重复成本，但尚未解决“如何从新领域原文自动产生高质量规则节点”。这说明 GDU 已具备可迁移的数据库生长骨架，但 Builder 仍是限制规模化的主要瓶颈。
