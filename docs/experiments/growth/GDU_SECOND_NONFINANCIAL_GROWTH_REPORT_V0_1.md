# GDU 第二次非财务生长实验报告 v0.1

## 实验目的

第一次正式生长依赖财务数字对账。本轮改用 PGKD 论文中的方法歧义，检验 GDU 能否处理无法通过算术决定真假的跨载体冲突。

问题是：

> PGKD 每轮训练新学生后，评估的是新模型还是旧模型？

## 生长前

v0.1 图已经保存 PGKD 的迭代过程、下一轮数据生成、下一轮学生训练和最佳模型返回，但没有保存“每轮究竟评估哪个模型”。

查询规划结果为 `gap`，缺少：

- `pgkd_evaluated_model_identity`；
- `pgkd_identity_source_resolved`。

系统从三个相邻方法节点出发，最多扩散两跳，然后定向回查 `train model`、`evaluate(model`、`model best` 等原文模式。为适应公式提取中空格、标点和上标丢失，备用检索增加了规范化匹配；图已有答案时仍不会启动原文搜索。

## 跨载体证据

人工视觉核对第 3—4 个物理页后，候选保存三类证据：

1. 方法正文：描述迭代生成下一轮数据、控制验证损失并返回验证集最佳模型；
2. Figure 1—2：把学生评估、数据生成和下一轮训练表示为循环；
3. Algorithm 1：第 8 行训练 `model^{i+1}`，第 9 行却评估 `model^i`，第 17 行又把 `model^i` 记为最佳模型。

正文和流程结构更自然地支持“评估更新后的学生”，算法字面索引则支持“评估旧学生”。来源本身没有说明哪一个是排版错误。

## 非数值提升门

候选不再使用金额残差，而必须通过：

- 文档和 Methods Context 一致；
- prose、figure、algorithm 三种载体齐全；
- Algorithm 1 的 `i+1` 与 `i` 字面索引完整保留；
- 结论明确标记为未消解歧义；
- 两种解释同时保留；
- 禁止无证据断言“必然是排版错误”。

修改候选，把第 9 行改写成评估 `model^{i+1}` 后，提升门会因旧模型索引证据消失而拒绝候选。

## 正式生长结果

通过验证后生成 `gdu-logic-method-slice-v0.2`：

- 信息节点：16 个；
- 方案节点：9 个；
- 版本事件：`GROWTH-PGKD-METHOD-001`；
- 新增两种相反解释、一个来源冲突元命题和一个禁止静默修正的边界命题。

Belnap 信息状态把“评估更新后模型”记录为 `BOTH`。在 Dung grounded semantics 下，两种互相反驳的具体解释均为 `undecided`；系统没有强行选择其中之一。

与此同时，“来源存在未消解歧义”是一个独立、可由三种载体共同支持的元结论，因此可以被接受并进入答案。

## 生长后回答

同一个问题由 `gap` 变成 `ready`，答案是：

> 来源对每轮被评估模型的身份存在未消解歧义：正文与流程图倾向更新后模型，Algorithm 1 字面索引则是旧模型。仅凭论文来源无法确定 Algorithm 1 是排版错误还是作者有意评估旧模型，不能静默改写索引。

“流程意图足以证明 Algorithm 1 只是排版错误”作为可废止经验推断被标记为 `rejected`。

## 失效与重放

撤销 Algorithm 1 的字面索引证据后：

- 旧模型解释失效；
- 来源冲突元命题失效；
- “来源未解决”边界失效；
- 原问题重新变成 `gap`，等待重新核对来源。

局部重算与全量重算一致。

使用固定输入、事件 ID 和时间独立重放 v0.2，输出逐字节一致，SHA-256 为：

`84054bd6f5ed53024736db3dbed784be80ff4c5f622eb65301e536b7a2e1a8bf`

## 阶段结论

第二次实验表明，GDU 的生长闭环不只适用于数值对账。它也能够把跨正文、图和算法的来源冲突生长为：

- 两个并存的具体解释；
- 一个可回答的“来源未消解”元结论；
- 一个禁止系统擅自修正来源的边界。

但本轮也暴露当前限制：候选提升门仍然针对具体任务编写。系统已经证明“可以安全生长”，尚未证明能自动生成适用于任意领域的验证规则。下一步应抽取财务与 PGKD 两个提升器的共同部分，判断哪些是通用门，哪些必须由领域插件提供。
