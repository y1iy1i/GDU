## 4. 结果复核发现的缺陷

候选桥接节点声称，列出的调整“最终形成”经营现金流 7,254.58 万元，但它实际列出的计算为：

```text
净利润                         -30,937,240.23
模型汇总的非现金项目           +38,340,603.38
模型汇总的营运资本项目         +49,434,873.71
---------------------------------------------
按候选节点可计算的结果          56,838,236.86
报告中的经营现金流              72,545,781.16
尚未解释的差额                  15,707,544.30
```

模型虽然在证据中看到了投资损失等项目，但没有把所有调节项纳入自己的汇总计算。因此它恢复了主要机制，却把“不完整解释”写成了近似完整解释。

现有验证器只检查：

- 是否恢复必需角色；
- 是否引用允许的证据；
- 存货方向是否正确；
- 两类机制是否连接到桥接节点；
- 是否保留现金总额边界。

它没有检查“候选节点声称完整解释时，数字能否闭合”。因此把该桥接节点自动标成 `machine_verified` 是过早晋级。

发现该问题后，实验代码已将自动生长节点的默认状态改为 `structurally_valid`。这个状态不会通过正式回答门；只有后续闭合检查或人工复核将其晋级为 `validated` 后，解释路径才可以用于正式答案。原始运行结果及其哈希保持不变。

## 5. 研究判断

本轮应分成两个结论：

1. **生长能力初步成立**：系统能识别缺失角色，并从相邻原文中恢复正确方向的机制节点和关系。
2. **自治写入尚不成立**：仅有结构和证据引用检查，不足以把语义桥接节点直接写入正式主干。

因此整体结论不是“GDU已经能自行学完整篇文章”，而是：

> GDU 已经展示了一次受问题驱动的局部生长，但新增的解释节点仍需要更强的闭合验证，才能从候选区进入正式知识图。

## 6. 对架构的直接修改要求

后续生长节点采用两级验证：

```text
模型生成
→ candidate
→ 证据引用、符号、范围等结构验证
→ structurally_valid
→ 数字闭合、反证搜索、语义范围验证
→ validated
```

其中：

- `structurally_valid` 节点可以用于继续搜索；
- 只有 `validated` 节点可以支撑正式答案；
- 如果节点使用“全部、最终形成、完全解释”等完整性表达，必须进行数字闭合或全文反证搜索；
- 无法闭合时应改写成“部分解释”并明确残差，而不是强行放行。

## 7. 下一实验

在不增加第二次模型调用的前提下，为候选桥接节点加入确定性闭合检查：

1. 解析候选声明的计算范围；
2. 汇总其引用的表格项目；
3. 计算候选路径结果与目标经营现金流的残差；
4. 残差超过阈值时保持 `structurally_valid`，不得晋级；
5. 将残差转化为新的推理缺口，再定向搜索遗漏调节项；
6. 直到闭合或明确回答“目前只能部分解释”。

这会把一次生长变成可连续迭代的生长循环，而不是一次模型补写。
