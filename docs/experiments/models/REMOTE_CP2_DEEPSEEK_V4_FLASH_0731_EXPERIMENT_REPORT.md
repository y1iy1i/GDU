# DeepSeek V4 Flash 0731 远程 CP2 实验报告

日期：2026-08-20

状态：在两次有界定向修正后通过；尚未进入 CP3。

## 实验简介

CP1 只确认“第二节位于第 8–12 页”。CP2 进一步测试模型能否在这段结构内部形成一个可保存的局部理解单元，而不是只把页面切成块或抄写数字。

本轮预登记任务聚焦三项数据：2025 年归母净利润、扣非归母净利润、非经常性损益合计。模型需要建立一个 semantic unit、三条来源断言和一条功能断言，并复用 CP1 已确认的结构与证据编号。

## 实验设置

- 服务：阿里云百炼北京区 Token Plan；
- 模型：`deepseek-v4-flash-0731`；
- 输入：Pilot 03 年报物理页 8–12；
- 既有状态：CP1 的 `PS-002` 与 `E-002`–`E-006`；
- 阶段：CP2，只允许 semantic_unit 与 assertion；
- 每次运行最大调用次数：1；
- 初始生成：1 次；
- 定向修正：2 次；
- 自动重试：0。

## 预登记验收条件

1. 至少生成一个 semantic unit、三条来源内容断言和一条功能断言；
2. 三个金额 `292,589,095.99`、`235,942,443.22`、`56,646,652.77` 必须完整出现；
3. 前两项必须引用第 9 页对应的 `E-003`，第三项必须引用第 11 页对应的 `E-005`；
4. 新对象之间只能用 `@handle` 交叉引用，规范 ID 由 Builder 分配；
5. 语义单元必须属于 `PS-002`，不得越界解释第三节；
6. 主要功能断言必须以三条内容断言为依据。

## 结果解读

本轮证明 DeepSeek 能在给定结构和页包内，把分散在第 9 页与第 11 页的相关数据组织成一个局部理解单元，并说明该组合帮助读者理解利润构成。这比单纯复制段落多了一步“语义组织”。

同时，初始生成和第一次修正暴露出明显不稳定性：模型理解了内容，但不能稳定遵守对象引用与复杂字段契约。CP2 的通过依赖两次定向修正，因此不能表述为“一次生成即可稳定构建 GDU”。

成功结果的摘要和功能说明使用了英文，事实断言为中文。这不影响本轮内容与接地验收，但属于呈现一致性问题；后续实验已增加统一使用简体中文的要求。

## 当前结论边界

可以得出：在人工限定页包、明确目标和两次有界修正内，模型可以产生合格的 CP2 局部语义单元。

不能得出：模型可以自动发现所有重要单元、一次稳定生成、完成跨章节关系、形成整篇生成计划，或证明 GDU 优于现有知识存储体系。
