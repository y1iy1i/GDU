## 实验简介

CP5 测试系统能否把 CP2–CP4 已接受的局部对象组织成一条可重新讲述的理解主线。由于当前实验只覆盖年报第二节，本轮产物被明确限定为“局部生成计划原型”，不能冒充整份 237 页年报的全局 GenerativePlan。

- 服务：阿里云百炼北京区 Token Plan；
- 模型：`deepseek-v4-flash-0731`；
- 输入：CP2 语义单元、CP3 断言与解释组、CP4 关系，以及年报物理页 9–12；
- 阶段：CP5，只允许 generative_plan；
- 实际 API 请求：1 次；
- 自动重试：0；
- 模型定向修正：0 次。

## 预登记验收条件

1. 计划必须完整包含 `purpose`、`core_meaning`、`content_selection`、`organization`、`constraints`；
2. 每段必须使用预登记引用，不能增加未知对象；
3. 不得在摘要中新增数字、因果关系、因素排序或公司级结论；
4. `organization` 必须按“利润口径—并行解释—不确定性边界”组织；
5. `constraints` 必须明确仅覆盖第二节局部样本、不代表整份年报，并禁止贡献排序。

初次本地语义判定错误地要求 `core_meaning.summary` 必须逐字出现“扣非”。模型实际写的是“利润口径差异”，同时引用了 `A-002` 和 `A-003`，具体扣非与非经常性内容并未丢失。

验收规则因此修正为：摘要可以压缩措辞，但必须通过规范引用保留具体含义。新增回归测试后，同一份原始模型结果离线重验通过，没有再次调用 API。

## 五段计划

- `purpose`：帮助读者理解局部样本中的利润口径、构成与改善原因；
- `core_meaning`：同时保留口径差异、经营改善、投资公允价值影响和不能排序的边界；
- `content_selection`：选择三项利润口径与原文改善原因作为最小充分材料；
- `organization`：先讲利润口径，再讲并行解释，最后讲不确定性约束；
- `constraints`：仅覆盖第二节局部样本，不代表整份年报，不能给因素排序。

## 结果解读

本轮说明 GDU 中的计划不是重新写一份摘要，而是用稳定引用规定“选择什么、按什么顺序讲、哪些边界必须保留”。摘要可以压缩表达，具体事实与关系由引用对象承担，因此不应把关键词逐字匹配误当作语义完整性。

## 当前结论边界

可以得出：DeepSeek 能在一次生成中把已接受的局部对象组织成五段合格计划，并诚实保留局部范围和不确定性。

不能得出：当前计划已经解释整份年报，Builder 可以冻结完整 GDU，或该计划能够回答第二节以外的问题。
