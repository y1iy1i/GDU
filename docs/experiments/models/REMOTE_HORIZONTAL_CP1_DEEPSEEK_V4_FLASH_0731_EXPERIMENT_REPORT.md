# GDU 横向扩展 CP1 实验报告

## 1. 实验目的

检验局部纵向链 CP1–CP6 完成后，GDU 的物理结构主干能否继续扩展到其他章节，而不是只对第二节有效。

本轮只处理第三节、第四节及相邻边界，不重复旧阶段。

## 2. 输入与预期结果

- 模型：`deepseek-v4-flash-0731`
- 权威来源：冻结的利通电子 2025 年年度报告 PDF
- 最小输入页：12、35、36、56、57
- 预注册边界：
  - 第三节“管理层讨论与分析”：物理页 12–36；
  - 第四节“公司治理、环境和社会”：物理页 36–57。
- 允许相邻章节共享边界页，因为第 36 页同时包含第三节末尾和第四节标题。

## 3. 运行结果

第一次调用未进入语义验收：模型将 `evidence_refs` 错放在候选对象顶层，违反适配器响应 Schema。

第二次调用通过响应 Schema 和 GDU 字段 Schema，并正确输出：

- 两个顶层章节，标题完全一致；
- 顺序分别为 3 和 4；
- 页范围分别为 12–36 和 36–57；
- 正确认出共享边界页 36。

但第二次输出缩短了证据摘录，同时沿用来源片段哈希，因而未通过严格的逐片段一致性检查。被拒结果 SHA-256：

`ff42ce8a582050bf089748fa111eb94dfccd8356653d065c54d711dfbaa29936`

## 4. Builder 调整与离线复验

实验脚本新增确定性证据绑定：保留模型生成的章节判断，但由程序直接从 `SourcePacket` 写入物理页 12、36、57 的完整摘录、定位符和哈希，并重新连接章节证据引用。

对第二次模型结果执行离线复验，不新增 API 调用。结果：

- 适配器响应 Schema：通过；
- GDU 字段 Schema：通过；
- 精确 PDF 证据绑定：通过；
- 两个章节标题、顺序和边界：通过；
- 最终对象：2 个物理结构节点、3 个证据节点。

通过结果 SHA-256：

`897a2eb25617d3e31cd6bfa9a7357d51f98296f1902ab38937850216ec6c6604`

## 5. 对实验的意义

本轮支持两个阶段性判断：

1. GDU 的四层主干可以从局部章节继续扩展，当前结果并非仅适用于第二节；
2. 小模型适合判断标题、层级和边界，不适合承担长证据的逐字复制。证据提取与哈希绑定应由确定性代码完成。

这不是对 GDU 整体优劣的最终结论。下一轮需要建立第三、第四节语义单元并测试跨章节关系，再与普通分块检索回答进行同题比较。
