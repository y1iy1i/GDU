# GDU 候选逻辑接口调试报告 v0.1

> 日期：2026-08-20  
> 对象：三层逻辑主干＋两个横向模块  
> 结论：最小接口可运行；发现并修复1个严格/可废止规则边界错误，仍有3项关键兼容性问题待验证。

## 1. 本轮范围

本轮没有调用模型，没有修改旧Schema和冻结基线，只建立一个确定性的逻辑试验台，检查：

```text
AIF式表示
→ ASPIC+式结构化论证
→ Dung grounded标签

Claim
→ Belnap四值信息状态

前提失效
→ TMS依赖重算＋PROV失效记录
```

## 2. 已通过案例

| 案例 | 结果 |
|---|---|
| 两个前提经严格规则形成一个结论 | 通过，联合前提未退化成两条独立支持边 |
| 无攻击论证进入grounded集合 | 通过，得到`accepted` |
| 同一命题同时有正反信息 | 通过，Belnap为`BOTH` |
| 两个论证互相rebut | 通过，grounded状态均为`undecided` |
| undercut攻击可废止Inference | 通过，目标论证`rejected`，原前提仍`accepted` |
| 不同Context直接rebut | 被接口拒绝，报告`rebut_scope_mismatch` |
| 一个前提失效 | 下游Inference和无其他支持的Claim失效 |
| 存在另一条有效Inference | 原路径失效，但结论继续有效 |
| 验证过程不修改输入图 | 通过 |

相关新旧逻辑测试合计19项全部通过。

## 3. 调试中发现并修复的问题

初始测试曾允许`undercut`攻击一个`strict`推理。这会混淆两种情况：

```text
严格规则：前提成立则结论必然成立
可废止规则：前提只形成可被推翻的推定
```

按照ASPIC+的结构，undercut针对可废止推理的适用性。严格推理如果产生错误，应该：

- 攻击其前提；
- 指出Context不适用；
- 或承认该规则原本就不应被分类为strict。

接口现已加入`strict_inference_cannot_be_undercut`约束。这说明分层不是简单存储分工，它能够迫使系统明确错误究竟发生在哪个逻辑位置。

## 4. 当前双状态结果

测试证明两套状态可以同时存在且含义不同：

```text
命题信息状态：BOTH
支持论证状态：undecided
反对论证状态：undecided
```

这说明Belnap状态没有在数据结构上妨碍Dung计算。但尚未证明Belnap带来了不可替代的功能；它是否冗余仍需消融。

## 5. 当前TMS/PROV结果

失效事件不会删除原图。重算产生新快照，并记录：

- `invalidated_by`事件；
- 当前有效Claim；
- 当前有效Inference；
- 替代Inference是否仍能维持结论。

这与逻辑主干能够连接，但本轮执行的是全量前向重算。尚未证明局部重算与全量重算等价。

## 6. 尚未解决的接口问题

### 6.1 多条论证路径尚未无损展开

当前最小编译器对每个Inference选择一组规范前提论证。如果同一个Claim有多条独立推导路径，完整ASPIC+映射应保留所有组合。否则可能漏掉一条不受攻击的替代论证。

### 6.2 Context目前只做完全相等比较

真实Context存在包含关系：

```text
2025全年 ⊃ 2025第四季度
合并口径 ⊃ 某些子公司
```

简单的相等/不等不足以判断能否rebut，需要明确Context的重叠、包含和互斥规则。

### 6.3 局部重算尚未证明正确

TMS下一接口实验必须比较：

```text
只重算受影响子图
vs
重新计算完整论证图
```

两者的Claim有效性和Dung标签必须完全一致，否则不能采用局部更新。

## 7. 当前判断

第一轮结果支持继续研究该组合，原因是：

- AIF式规则应用节点能够保留联合前提；
- ASPIC+攻击位置能区分“前提错”和“推理方式错”；
- Dung grounded语义能够保守处理互相攻击；
- Belnap信息状态与论证接受状态暂未发生语义覆盖；
- TMS/PROV能够在不删除历史的情况下维护依赖。

但现在只能称为“最小接口可运行”，还不能称为逻辑架构已经自洽。下一次接口调试优先解决多条推导路径的无损展开，因为它会直接影响攻击计算和节点失效后的答案正确性。
