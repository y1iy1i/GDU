# GDU 候选逻辑接口调试报告 v0.2

> 日期：2026-08-20  
> 本轮问题：同一结论有多条独立推导路径时，AIF→ASPIC+接口是否无损  
> 结论：最小案例通过；每条替代路径可独立接受或拒绝，不再因一条路径被攻击而错误撤销整个结论。

## 1. v0.1缺陷

v0.1编译器对一个Inference的每个前提只选择一条规范论证。如果前提Claim有两条来源：

```text
A → M
B → M
M → C
```

它只会保留：

```text
A → M → C
```

或：

```text
B → M → C
```

这会导致攻击A路径时，系统误以为C已经没有支持，即使B路径仍然有效。

## 2. 修改

接口现在按以下规则展开：

1. 先建立Inference之间的生产者—消费者依赖；
2. 按稳定拓扑顺序处理Inference；
3. 为每个前提取得全部可用子论证；
4. 对联合前提计算笛卡尔组合；
5. 每个不同组合形成一个独立StructuredArgument；
6. 下游论证保存完整subargument集合；
7. undercut某个Inference时，只攻击包含该Inference的路径及其下游。

## 3. 结果

在以下结构中：

```text
A ─I-A→ M ─┐
            ├─I-FINAL→ C
B ─I-B→ M ─┘
```

系统生成两个C论证：

```text
Argument C-1 = {A, I-A, I-FINAL}
Argument C-2 = {B, I-B, I-FINAL}
```

加入：

```text
U ─undercut→ I-A
```

grounded结果为：

```text
C-1：rejected
C-2：accepted
```

因此C仍然至少有一条可接受论证。攻击不再错误扩散到逻辑上独立的B路径。

## 4. 推理环处理

无损展开遇到推理依赖环时可能无限生成更深的论证：

```text
A → B → A → ...
```

v0.2暂时禁止Inference依赖环，并报告：

```text
cyclic_inference_dependency
```

攻击环仍然允许，因为互相rebut正是Dung框架需要表达的结构。禁止的是“用自己的派生结果再次证明自己”的推理构造环。

## 5. 测试

- 逻辑接口测试：11项通过；
- 与自修复、生长和外部复验组合的相关测试：合计24项通过；
- 远程模型调用：0；
- API费用：0。

## 6. 新暴露的复杂度边界

无损保留多条推理路径可能产生组合增长。假设三个前提分别有2、3、4条论证，则一个Inference可能产生：

```text
2 × 3 × 4 = 24
```

条结构化论证。

因此当前优先保证语义正确，不在逻辑层随意删路径。后续性能优化只能采用：

- 等价论证共享子图；
- 延迟展开；
- 针对问题只实例化相关论证；
- 对证明结构做符号压缩。

不能重新退回“任意选择一条规范路径”，否则会再次破坏攻击和失效传播的正确性。

## 7. 当前判断

第一项接口缺陷已经在最小案例上解决。下一项应处理Context的包含、重叠和互斥，因为不同Context是否能形成rebut会直接决定攻击图是否正确。
